# 个人分支约定

> 这些是我们这个 fork 自己的约定。上游规则看仓库根目录的 `AGENTS.md`，两边冲突时以上游为准。

## 仓库和分支

- `origin` = `dtyjasper-prog/orca`（自己的 fork），`upstream` = `stablyai/orca`（官方）。
- `main`：自己的主线，内容是官方 main 加上已经做完的功能。
- 每个功能单独开一个分支，名字叫 `feat/功能名`（例如 `feat/crew-graph`、`feat/dashboard-dragout`），做完合并回 `main`。
- 同步官方更新：`git fetch upstream`，然后 `git merge upstream/main` 进 `main`。用 merge 不用 rebase，避免改写已经推上去的历史。

## 减少和官方的冲突

- 尽量新建文件，少改上游原有的文件。必须改的地方只做最小改动，然后在改动处挂一个新组件或新函数。
- 新代码放在上游已有的对应目录里，例如派工图放 `src/renderer/src/components/orchestration-crew/graph/`。
- 不改上游的 `AGENTS.md`、CI 配置和版本号。
- 只有这个 fork 自己用的文档，统一放 `docs/fork/`。

## 本机环境

- Node 24，用 fnm 管理，装在 `D:\Me\Develop\apps\fnm`。用户环境变量 `FNM_DIR` 指向 `D:\Me\Develop\apps\fnm\node-versions`。全局的 Node 26 不要动。
  跑命令时这样写：`fnm exec --using 24 pnpm.cmd <命令>`（Windows 上要写 `pnpm.cmd`、`npm.cmd`）。
- C++ 编译工具：VS Build Tools 2022，装在 `D:\Me\Develop\apps\VSBuildTools`（编译 node-pty 等原生模块要用）。
- pnpm 公共缓存在 `D:\Me\Develop\cache\pnpm-store`，2026-11-19 从 `D:\.pnpm-store` 搬过来的。
- 用户环境变量 `ORCA_PNPM_GLOBAL_VIRTUAL_STORE=0`：依赖放在项目自己的 `node_modules\.pnpm` 里，不靠公共缓存里的链接。原因是公共缓存一搬家，那些链接就全断了。
- 删 `node_modules` 要用 `cmd /c rmdir /s /q`，不要用 `Remove-Item -Recurse`，后者可能顺着链接删进公共缓存。

## 运行

- 开发模式：`pnpm dev`，跟已装的官方 Orca 同时存在。
- 在 Claude 桌面版的终端里启动开发版时，必须加 `ORCA_DEV_USER_DATA_PATH=D:\Me\Develop\cache\orca-dev-profile`。原因：桌面版会把写入 `AppData\Roaming` 的文件转到它自己的沙盒目录，Orca 在里面改文件名时会报 EXDEV（跨盘移动）错误，启动不了。
- 第一次启动加 `--seed-profile`，从正式版复制项目和工作区数据，正式版的数据不会被改。
- 需要自动启动的时候加 `ORCA_BACKGROUND_LAUNCH=1`，不抢桌面焦点。
