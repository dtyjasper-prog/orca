## 4. 第一阶段要做的

### 功能 A：派工任务关系图

- 在派工面板里加一个「列表 / 关系图」切换。
- 关系图里一个节点代表一个任务或执行者，线代表「谁派给谁」和「谁等谁」（依赖）。
- 节点颜色按状态区分：已派出、进行中、等你回复、卡住、完成、失败。颜色只用已有的设计变量。
- 点节点会跳到对应的工作树或终端，悬停时显示任务标题、助手类型和耗时。
- 状态变化时图会实时更新，不用手动刷新。
- 画图库：先看上游有没有现成的依赖，没有的话再问用户。

**验收**：用 orchestration 派出一个至少 3 个任务的派工，任务之间有依赖。关系图上节点数和连线跟实际派工一致；某个任务完成后，节点颜色在几秒内变过来；点节点能跳过去。

> 更正：用户说的「工作版」是**工作区板**（Workspace board，代码在 `src/renderer/src/components/sidebar/workspace-board/`，按状态把工作树分列摆放），不是代理仪表盘（Agent Dashboard）。工作区板现在只能以抽屉形式出现在侧栏旁边，没有独立窗口。

### 功能 B：工作区板拖出成独立窗口

- 按住工作区板的标题栏往主窗口外面拖，松手就在那个位置开一个独立窗口。另外在标题栏加一个「弹出」按钮。
- 独立窗口记住上次的位置和大小（适合放在副屏）。
- 窗口置顶可以开关，开关放在标题栏。
- 把独立窗口拖回主窗口的侧栏区域就合并，重新以抽屉形式显示。关掉独立窗口也会回到抽屉。
- 独立窗口里的数据和操作（搜索、改状态、打开工作树）跟主窗口实时同步。可以参考代理仪表盘现成的弹出窗口（`components/dashboard-popout/`、`dashboard/popout-bridge/`）来写。

**验收**：

1. 往外拖能开出独立窗口，在主窗口改了状态，独立窗口里几秒内跟着变；反过来也一样。
2. 关掉 Orca 再打开，独立窗口回到原来的位置，大小也不变。
3. 打开置顶以后，切到别的程序，独立窗口仍然在最上面。
4. 拖回侧栏或关掉窗口，主窗口能正常用抽屉打开工作区板。

### 功能 C：工作区板分区大小可调

现在的情况：所有列共用一个宽度（220 到 520 像素），拖一列其他列跟着变；整块板子宽度固定，最宽 1294 像素。

- **每一列单独调宽度**：各列分别记住自己的宽度，双击分界线恢复默认。老设置里那个统一宽度，作为每一列的初始值。
- **整块板子的宽度可以拖**：抽屉模式下右边缘能拖，去掉 1294 像素的上限，宽度记住。独立窗口模式下跟着窗口大小走。
- **列可以折叠**：点列头的按钮把这一列缩成窄条，只显示列名和数量，再点一下展开。折叠状态记住。

**验收**：

1. 分别把两列调成不同宽度，重启后宽度不变；双击分界线后恢复默认宽度。
2. 把抽屉拖宽到超过 1294 像素，重启后宽度不变。
3. 折叠一列，它变成窄条，数量显示正确；卡片还能拖进折叠的列里改状态。重启后仍是折叠的。

## 5. 不在第一阶段做的

- 时间线、结果汇总视图、侧栏工作区卡片改造、全局总览页
- 手机端（`mobile/`）、网页端
- 给官方提 PR。等功能稳定了再说

## 6. 做的顺序

先做 C（分区大小，只改前端，最简单），再做 B（独立窗口，要改主进程），最后做 A（关系图）。每做完一个功能，开一个 `feat/` 分支提交，验收通过后合并回 `main`。

以后再考虑的自定义：卡片显示哪些字段、分组方式、保存视图、紧凑模式。

## 7. 怎么验证

- 类型检查：`pnpm tc`
- 改动检查：`pnpm check:changed`（上游要求提交前跑）
- 实际界面：`ORCA_BACKGROUND_LAUNCH=1` 后台启动开发版，用 CDP（Chrome 调试协议）截图检查，不抢桌面焦点
